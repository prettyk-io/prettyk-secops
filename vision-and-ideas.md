# PrettyK — Vision and Ideas

> **Статус:** рабочее видение / evolve · 24 августа 2026 г.
>
> Это не CANON, не backlog и не обязательство реализовать всё перечисленное. Документ фиксирует фокус проекта, продуктовые связи и идеи для открытого инженерного диалога.

---

## 1. Главная мысль и приоритеты

PrettyK начинался как DAST scanner, но вырос в мощную платформу исполнения сценариев, работы с браузером и анализа безопасности.

### Наши приоритеты:

1. **Приоритет №1 — DAST & SecOps Platform (Флагман)**
   * Браузерное исследование (Playwright browser context, discovery, обход SPA).
   * Сценарный движок атак и умный фаззинг (DSL, мутации, генерация пэйлоадов).
   * ZAP / API / Web security checks.
   * Нормализация находок (fingerprints, lifecycle, дедупликация).
   * Честные Quality Gates и Evidence (видео, скриншоты, HAR, request/response proof).

2. **Приоритет №2 — Automation alone / Automation Lab**
   * Выделение нашего мощного браузерного и API execution engine в самостоятельный инструмент чистой автоматизации.
   * E2E-тестирование, RPA, автоматизация рутинных сценариев без SecOps-специфики.
   * Единый DSL и раннер как для тестов безопасности, так и для бизнес-автоматизации.

3. **Идея на отдалённое будущее (Parking Lot / Evolve)**
   * *Delivery Fabric / Cosmo-style обвязка:* иерархия репозиториев (L0 библиотеки $\rightarrow$ L1 сервисы $\rightarrow$ L2 группы), цепочки внешних сканеров (Sonar/Trivy/PTAI) и массовый деплой. Это интересная концепция, но сейчас она отложена — держим фокус на DAST и Automation.

## 2. Аксиома команды

Максим способен вывезти проект один: архитектуру, логику, бэкенд и фронтенд — вместе с AI-агентами. Это не поиск «спасителя» и не закрытие дыр любой ценой.

Люди подключаются ради другого:
* свежие взгляды, идеи и здоровая инженерная критика;
* параллельное ускорение разработки;
* независимая валидация архитектурных решений;
* радость совместного создания большого продукта.

**Вера** — близкий друг и UX/UI дизайнер, отвечающая за то, чтобы сложнейшая инженерная система была удобной, эстетичной и понятной человеку.

## 3. Продуктовые поверхности

### 3.1. Web IDE / Security Workbench
Единое рабочее пространство:
* Редактирование сценариев на PrettyK DSL с автодополнением и диагностикой (Monaco / LSP).
* Встроенный изолированный терминал и Run Console (xterm.js).
* Инспектор запросов/ответов, живые логи и сбор Evidence.
* Replay отдельных шагов и отладка поведения.

### 3.2. Studio Graph & Steps
Проектирование логики:
* Граф шагов со свёртками (collapses) от верхнеуровневого flow до параметров конкретного шага.
* Двусторонняя синхронизация: DSL $\leftrightarrow$ Visual Graph (изменение одного обновляет другое без потерь).

### 3.3. War Zone Canvas Mode
Оперативный центр управления:
* Наблюдение за несколькими параллельными прогонами в реальном времени.
* Статусы воркеров, таймлайн выполнения, мгновенный доступ к браузерным сессиям и ошибкам.

### 3.4. Admin & Control Plane
Управление платформой:
* Ролевая модель (RBAC/Capabilities) и пространства (Spaces).
* Инвентарь целей (Targets), разрешённый Scope и политики безопасности (Policies).
* Управление жизненным циклом находок (Findings) и аудит действий.

### 3.5. QWEN (Contextual Root-Cause Engine)
Окультуренный AI-слой поверх данных:
* Не «глупый чат-бот», а аналитик контекста выполнения и доказательств.
* Объяснение причин блокировки гейтов, корреляция находок, генерация предложений по исправлению.
* AI предлагает и объясняет, но **не имеет права** самостоятельно расширять Scope или запускать деструктивные действия.

## 4. Архитектурный стек (High-Level Snapshot)

Никаких простыней из сотен библиотек — только фундаментальные слои и движение данных:

```text
1. Engine & Runtime (Backend)
   • Python — DSL-интерпретатор, сценарный движок, оркестрация
   • Playwright Browser Core + ZAP Engine — headless/headed браузер, API-пробы, фаззинг

2. State & Persistence (Durable & Realtime)
   • PostgreSQL 16 — durable Source of Truth (прогоны, находки, политики, аудит)
   • Valkey 8 — pub/sub, SSE-стриминг телеметрии, эфемерный кэш

3. Workbench & Frontend
   • TypeScript + React — Web IDE, Studio Graph, War Zone, Admin UI
   • Monaco Editor (DSL language support) + xterm.js (консоли воркеров)

4. Execution Substrate (Infra)
   • Docker / Isolated Worker Pool — запуск тяжелых прогонов с изоляцией ресурсов
```

## 5. Подход к диалогу с новыми инженерами

1. **Без давления и навязчивых продаж:** Не «купи стартап», а «посмотри живую инженерную систему и дай обратную связь».
2. **Фокус на бэкенд-архитектуре:** Показать сильные инженерные вызовы — стейт-машины прогонов, параллельное исполнение воркеров, надежное хранение данных и событийные шины.
3. **Демо вместо теории:** 10 минут показа живого прогона на стенде скажут больше любых презентаций.
