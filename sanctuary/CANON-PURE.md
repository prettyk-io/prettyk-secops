# CANON-PURE — спека коробки (secops-lab-pure)

> **Sanctuary**. Slice: 13 августа 2026. Отполированная спека коробки (CANON BASE).
> Основа: `docs/KDTZaproxy.md` (техпаспорт) + `docs/canon/runtime-shell.md` + `docs/canon/*`.
> Без имени продукта. Без заказчика. Без банка.

Коробка — инструмент оператора ИБ для проведения динамических проверок безопасности
веб-приложений как **повторяемой дисциплины**, а не как единичной галочки в пайплайне.

---

## 1. Назначение

Интерпретатор декларативных сценариев проверки. В одном сценарии — данные, браузер, HTTP и
управление сканером. Оркестратор исполняет сценарий, складывает свидетельства на диск и
отдаёт код выхода для CI.

Проверка описывается **декларативно** — автор задаёт план, шаги, границы и ожидания, а
runtime готовит браузер, сканер, аутентификацию и строит поток данных.

## 2. Контур исполнения

```text
Декларативный сценарий
  → оркестратор (Controller)
  → браузер через MITM-прокси сканера
  → действия сканера + отчёты на диск
  → quality gate по настраиваемому порогу серьёзности
  → финализация: структурированный отчёт + опциональный импорт в реестр находок
```

Внешняя точка запуска одна — CLI. Отдельная ветка `--validate-only` проверяет сценарий
без запуска браузера и сканера.

## 3. Язык и действия

Три представления сценария, сводящиеся к одному runtime-контракту:

```text
Предметно-ориентированный язык (prettyK) → AST → wire → ActionFactory → адаптер
```

- **prettyK** — авторский язык: данные, ветвления, циклы, обработка ошибок, группы, page calls.
- **WireK** — машинный диагностический формат `component|action|args` (то, что реально исполняется).
- **MethodId** — русские имена действий, отображаемые в wire.

## 4. Архитектура

Два контура: **исполнение** (сценарий → адаптеры → цель) и **финализация отчётов**.
Сканер пишет файлы на диск; импорт в реестр находок делает оркестратор, не сканер.

| Компонент | Ответственность |
|---|---|
| манифест (SoT) | Декларативное описание проверки; из него производны форма и редактор |
| runtime-модель | Загрузка и базовая валидация |
| Controller | Lifecycle прогона, сценарии, данные, quality gate, запись свидетельств |
| LanguageEngine | Разбор языка и построение AST |
| MethodId resolver | Русские имена → wire-действия |
| ActionFactory | Регистрация и вызов действий |
| Адаптеры | Границы интеграции: WebDriver, сканер, HTTP, данные |

Controller не обращается к сканеру/браузеру в обход адаптеров.

## 5. Роли стенда (не путать)

| Роль | Вопрос | Не является |
|---|---|---|
| WebDriver | Кто кликает в UI? | Отчётом / реестром находок |
| Selenium Grid (опц.) | Remote WD + UI сессий | Оболочкой коробки |
| Live-оболочка | Картинка + ленты сценария/сканера во время прогона | Отчётом |
| Структурированный отчёт (Allure-класс) | HTML шагов после прогона | Live |
| Реестр находок (Dojo-класс) | Учёт findings | Исполнением шагов |
| Сканер (ZAP-класс) | MITM + API сканера | Браузерной фермой |

Формула: **сценарий → оркестратор → WebDriver (±Grid) → трафик через сканер → свидетельства
(отчёт/сканер/реестр) + опционально Live**.

## 6. Жизненный цикл прогона

1. Загрузка сценария, env/секреты, runtime-модель.
2. Controller подключает сканер, listener прокси, регистрирует действия.
3. Браузер стартует при первом браузерном действии.
4. Тайм-ауты и auth bootstrap.
5. Для каждого сценария: свидетельства, тест-результат, поток данных.
6. Шаги разбираются в AST/wire и исполняются через фабрику действий.
7. `save_as`, retry, failsafe, `continue_on_failure` применяются к листьям.
8. После сценария — финальные отчёты, запрос findings от заданного порога.
9. Финализация: shutdown браузера, генерация отчёта, опциональный импорт в реестр.

## 7. Результат процесса

| Код | Смысл |
|---:|---|
| `0` | Исполнение без ошибки, отчёты доступны, gate пройден или отключён |
| `1` | Ошибка загрузки / инициализации / исполнения; отсутствует требуемый отчёт |
| `2` | Исполнение ок, но gate не пройден |

Порог gate задаётся серьёзностью (`High` по умолчанию). Ошибка чтения findings по умолчанию
fail-closed.

## 8. Границы доверия

- Сценарий — исполняемый вход; поступает из доверенного источника.
- Сканер получает доступ к целевой сети и модифицирует трафик.
- Секреты и персональные данные в свидетельствах — под контролем; не светить в логах.
- Токены реестра находок — только через защищённое окружение.
- Airgap — целевая модель поставки; без CDN и внешних API.

## 9. Честные границы

- Это операторский инструмент проверки, **не** промышленный портал SDLC.
- Пайплайн и его оркестрация — отдельный контур; коробка стоит **рядом**, не вместо.
- Grid UI ≠ смотреть сценарий; видео ≠ интерактивная сессия.
- Полный offline-бандл / SBOM / закреплённые digest — целевая модель, не текущий статус.
