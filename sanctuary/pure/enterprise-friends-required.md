# ENTERPRISE-FRIENDS-REQUIRED: планка Enterprise

> **CANON** — hub topic. Slice: **16 августа 2026** (2FA: зачисление по явной просьбе владельца).
> Pure-канон: что должно быть у коробки, чтобы называться «enterprise» и продаваться в контур заказчика.
> Реестр: [`INDEX.md`](INDEX.md). Смежное: [`brand-strategy.md`](brand-strategy.md) (позиционирование), [`auth-roles.md`](auth-roles.md), [`admission.md`](admission.md), [`split-canon.md`](split-canon.md).
> Патчи через 2FA.

## 1. Зачем

Enterprise-планка — **граница между «инструментом для оператора» и «продуктом для организации»**.
Пока коробка не перешла эту планку, честно говорить: «операторский инструмент», а не «enterprise».
Список ниже — чеклист, что достроить, чтобы называться enterprise.

## 2. Обязательный минимум (без этого — не enterprise)

| # | Требование | Зачем | Связанный канон |
|---|---|---|---|
| 1 | **SSO** (OIDC / SAML) | Вход через корпоративный IdP, а не только локальные учётки | [`auth-roles.md`](auth-roles.md) |
| 2 | **RBAC** | Ролевой доступ: admin / nshr / expert и т.п., без «один админ на всё» | [`auth-roles.md`](auth-roles.md) |
| 3 | **Аудит-лог** | Кто, что, когда запускал/менял — прослеживаемость для актов | [`admission.md`](admission.md) |
| 4 | **Self-host / airgap** | Развёртывание в изолированном контуре, без CDN и внешних API | [`split-canon.md`](split-canon.md) |
| 5 | **Secrets management** | Токены/секреты — только через защищённое окружение, не в логах | [`admin-integrations.md`](admin-integrations.md) |
| 6 | **Версия / SBOM / закреплённые digest** | Поставка с фиксированными артефактами | [`split-canon.md`](split-canon.md) |

## 3. Желаемый уровень (продажа крупным, РФ-контур)

| # | Требование | Зачем |
|---|---|---|
| 7 | **Лицензирование / квоты** | Контроль объёма (сканы/прогоны/пользователи) |
| 8 | **SLA / поддержка** | Гарантированный отклик, а не «когда-нибудь» |
| 9 | **Compliance-матрица** | ГОСТ Р, ФСТЭК, OWASP, GDPR-ready — какие регуляции закрываем |
| 10 | **Отчётность для утверждения актом** | Утверждаемый отчёт + вердикт допуска | [`admission.md`](admission.md) |
| 11 | **Multi-tenant / инстансы** | Разделение организаций/проектов |

## 4. Чего НЕ обещаем (честные границы)

- Коробка — операторский инструмент проверки, **не** промышленный портал SDLC.
- Пайплайн и его оркестрация — отдельный контур; коробка стоит **рядом**, не вместо.
- Enterprise-планка — **целевая модель**, не текущий статус. Каждый пункт выше — отдельная работа.

## 5. Правило честности

Позиционирование «enterprise» допустимо **только** когда §2 закрыт. До того — «операторский
инструмент / коробка». Не раздувать ожидания заказчика, пока планка не пройдена.
