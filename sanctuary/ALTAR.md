## 1. RJSF и JSON Schema — в стену

**Было:** форма редактора генерировалась из `docs/manifest.json` через `@rjsf/core`. Любое изменение поля требовало правки JSON Schema → правки формы → правки валидации. Сотни строк `uiSchema`, `"oneOf"` с `"const"`, RJSF-виджеты для каждого типа поля. Китайская команда не могла добавить кнопку без ломания всей формы.

**Стало:** прямой React-маппер. Pydantic на бэкенде — machine-контракт. Фронтенд рендерит поля напрямую, без генератора. `docs/manifest.json` — legacy reference, форма больше не производится из него.

**Эпик:** `REGULATION-EDITOR-SPLIT`, `RK-RJSF-KILL-SPLIT`.  
**Файлов:** 40+ удалено, 30+ переписано.  
**Результат:** форма редактируется за минуту вместо дня. Зависимость `@rjsf/core` выпилена.

## 4. Playwright Browser Core — новая браузерная подсистема

**Было:** только Selenium WebDriver. CDP через `driver.execute_cdp_cmd()`. Discovery recorder — самописные 90 строк на сыром CDP.

**Стало:** `pw-browser-core` в Sanctuary. Три режима:
- `launch()` — автономный браузер для прогонов/discovery  
- `connectOverCDP()` — живая сессия оператора через Chrome `:9222`  
- `BrowserContext × N` — multi-role изоляция за 10 мс

Четыре движка: bundled Chromium (default), Google Chrome, Firefox, WebKit.  
Headless и headed в одном адаптере.

**Файлы:** `orchestrator/browser/playwright_runtime.py` (190 строк), `orchestrator/adapters/playwright_adapter.py` (420 строк).  
**Smoke:** Chromium headless запущен и закрыт без ошибок.  
**Канон:** `sanctuary/pure/pw-browser-core.md` (13 разделов, 9 эпиков).

- `ZapContextInjector` — авто-проливка в ZAP Sites Tree
- `CorpusFuzzer` — собственный мутационный фаззер (50+ векторов, sniper/cluster-bomb)
- `FuzzReporter` — классификация аномалий
- `AdmissionFilter` — gate по severity

**Тестов:** 41/41 зелёные.

Мы перестали быть «ещё одним тестовым фреймворком». Мы стали чем-то, что не зависит ни от чьей внешней хуйни. Хотим — добавили браузер. Хотим — ИИ. Хотим — новый фронтенд-стек. Никакой банковский архитектор не скажет «это не согласовано», потому что коробка приносит всё своё.

## 11. Valkey 8 — Redis без лицензионного геморроя

**Было:** Redis в стеке DefectDojo (через `valkey/valkey:8-alpine`). Вопрос «а почему не просто Redis?» висел без ответа.

**Стало:** Valkey 8 (BSD) как единственный in-memory стек. Свободный форк Redis 7.2 под Linux Foundation. Контрибьюторы: AWS, Google, Oracle, Ericsson, Snap. DefectDojo уже мигрировал.

**Решение:** 24 августа 2026. Максим: «Динозавры пусть хоть говно жрут свое, у нас все эталонно свежее.» Принято единогласно.

## 12. PostgreSQL 16 — единый источник истины

**Было:** NDJSON и JSON-файлы как база данных. `runs_index.ndjson`, `checks_registry.json`, `current.json`, `diary_*.ndjson`. Без схемы, без миграций, без foreign keys, без транзакций. Достойно прототипа — недостойно продукта.

**Стало:** PostgreSQL 16. Единый source of truth для всего структурного. Better Auth рекомендует. DefectDojo и SonarQube уже на нём — не плодим зоопарк.

**Что держит:**
- users, sessions, accounts (Better Auth)
- profiles, capabilities, preferences
- api_keys, audit_log
- checks_registry (вместо JSON)
- runs_index (вместо NDJSON)
- findings, policies, targets
- artifacts_index

**Почему не MySQL:** JSONB слабее. DefectDojo не на MySQL — зоопарк.
**Почему не MongoDB:** Документная база без схемы. Auth и runs с чёткими связями — не её зона.
**Почему не SQLite:** SQLite остаётся для Pure Box (один бинарник). Для enterprise — PostgreSQL.

**Урок Космопорта:** Redis не виноват. Виноват тот, кто сделал его источником истины состояния джобов. Мигнул стенд — Redis пуст — «кого опрашивали? хер знает». Правильно: PostgreSQL — истина, Valkey — кэш. Всегда можно перестроить кэш из PostgreSQL за миллисекунды.

**Решение:** 24 августа 2026. PostgreSQL 16 approved. 0 тезисов против. Принято единогласно.
