## Дело № 1: Сквозной прогон — от запуска до replay

**Что проверяем:** цикл "запуск в Editor → live стрим в Monitor → job exit → видео → playhead".

### Чеклист

- [ ] **А-1.** Запустить пайплайн кнопкой «Запустить» в Editor (Результаты). Дождаться появления `run_id`.
- [ ] **А-2.** Открыть Monitor (`http://127.0.0.1:8767/?run_id=<run_id>&check_id=<check_id>`). Убедиться, что заголовок показывает `SecOps Lab Monitoring` (wordmark унифицирован).
- [ ] **А-3.** Досмотреть стрим до job exit — не обновляя окно. Убедиться, что после завершения прогона VNC-iframe сменился `<video>` с записанным WebM.
- [ ] **А-4.** В режимах **focus** (view 1) и **observer** (view 2) — под хедером появился playhead (полоса с ползунком, таймером, маркерами).

### Playhead

- [ ] **А-5.** Playhead — **чёрная полоса**. Над видео — до границы контейнера (ширина = ширина видео).
  - Слева: кнопки Play/Pause/Stop.
  - Live-индикатор: **зелёная пульсирующая кнопка** с надписью «live».
- [ ] **А-6.** Внутри контейнера с логами (focus-inspector справа) — playhead **вшит в log-панель**, без изменения стиля (CSS как у log container).
- [ ] **А-7.** Ползунок можно **отмотать назад** (влево), **задержать**, **двигать куда угодно**.
- [ ] **А-8.** При движении ползунка:
  - Таймер (`currentTime` / `duration`) динамически обновляется.
  - Логи фильтруются по времени — события с `ts ≤ currentTime` видны, остальные скрыты.
  - Видео (в replay-режиме) проматывается синхронно (`video.currentTime = playhead.currentTime`).
  - Каретка `execution-rail` (слоты current/next/past) обновляется — методы **человекочитаемые** (латиница, не raw hex).

### Дополнительно

- [ ] **А-9.** В режиме **split** (view 3: видео/лог 50/50) — playhead виден, работает.
- [ ] **А-10.** Маркеры (STEP, ERROR, HIGH, scanner) на playhead — кликабельны, прыгают к моменту.

## Дело № 2: HomePage Monitor

**Что проверяем:** `http://127.0.0.1:8767/` (без `run_id`).

### Требования (распарсены из формулировки Максима)

| # | Требование | Проверка |
|---|---|---|
| **HP-1** | HomePage показывает **только список apps** (не live-контент) | Открыть `:8767/` → видна таблица apps, нет VNC/логов |
| **HP-2** | Сортировка: **чем свежее последний запуск instance_run_id — тем выше app в таблице** | Первый app — тот, у кого последний `last_run_ts` максимальный |
| **HP-3** | **Вторичная сортировка:** по дате **первого запуска** (инициализация app-code = первый запуск пайпа для этого app-code, а не создание app-code в принципе) | При равных `last_run_ts` — выше тот, у кого раньше `first_run_ts` |
| **HP-4** | Таблица **динамическая** — рефрешится при новом `run_id` для любого `instance_id` и app | Запустить новый прогон → HomePage обновляет таблицу без F5 |
| **HP-5** | Элементы таблицы — **коллапсы**. Клик по app-code раскрывает/сворачивает | Клик → стрелка разворачивается, видны deploy-строки |
| **HP-6** | Внутри коллапса app-code — **N коллапсов по deployments** (сколько deploy_url у этого app) | Раскрыть app → видны строки deploy_url |
| **HP-7** | Внутри каждого deploy — **лейбл instance_id** проверки со ссылкой на вкладку «Регламент» релевантного instanceId | ⚠️ **BUG: см. эпик MH-FIX-LINKS ниже** |
| **HP-8** | Pagination: **10 строк** (app-коллапсов) на страницу | Таблица показывает ≤10 app-строк, кнопки «Назад/Вперёд» |
| **HP-9** | В коллапсе **app-code — ссылка на app в портале АС Космопорт** | ⚠️ **Заглушка (без URL)** — это корректно, интеграция отложена |

## Обнаруженный дефект: MH-FIX-LINKS

**Серьёзность:** P0 (неверная навигация из списка запусков → стрим).

**Суть:** клик по проверке в списке запусков (HomePage Monitor) ведёт на **форму редактора**, а должен вести на **живой стрим этой проверки** (экран/видео/логи прогона).

**Вывод:** проблема не в том, что ссылка битая (форма открывается), а в том, что ссылка ведёт **не туда**. Нужно, чтобы из списка запусков пользователь попадал на стрим проверки, а не в редактор.

Создан эпик: **MH-FIX-LINKS** в `docs/backlog.md`.
