Инженерная платформа для тестирования безопасности (DAST) и автоматизации браузерных и API сценариев.

Жизненный цикл

1 Authoring — авторинг
Monaco Editor ↔ Studio Graph = единая модель DSL/Graph

Сценарий описывается на человекочитаемом DSL или строится визуально в графе. Изменение в одной проекции мгновенно отражается в другой.

▼
2 DSL Engine — компиляция
Текст DSL → Парсер / Лексер → AST → Pretty → Wire
Что происходит на каждом шаге
  • AST — абстрактное синтаксическое дерево: структурное представление сценария
  • Pretty — нормализация, раскрытие импортов, резолвинг ссылок между страницами и сценариями, валидация типов
  • Wire — исполняемый IR (intermediate representation), который получает оркестратор
▼
3 Control Plane — контрольная плоскость
Оркестратор получает Wire
Auth / RBAC → Policy / Scope → Preflight → Run State Machine

Проверяются права оператора, разрешённый scope и политики. Preflight подтверждает, что запуск можно выполнять. Run State Machine ведёт запуск через состояния:

draft → approved → queued → running → succeeded / failed / cancelled
▼

Аномалии ответов

Интерпретатор читает Wire, проходит по шагам и через контроллер направляет команды адаптерам: Playwright (CDP) — браузер, scanner (API) — сканирование, Fuzzer — мутации. Каждый адаптер работает под контролем Run State Machine.

▼
5 Results & Evidence — результаты и финализация
Findings + Evidence + Quality Gate
PostgreSQL 16
Запуски, находки, аудит, политики
MinIO / S3
Скриншоты, HAR, видео, артефакты

Finding получает fingerprint, дедуплицируется по истории запусков и проходит через lifecycle: open → accepted / risk-accepted → fixed → verified.
