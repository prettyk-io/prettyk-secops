## 2. Что надо перепокрыть / добить (кандидаты, условно)

1. **Живой CDP run** — не unit: сценарий «клик на Juice Shop → не-mock событие →
   proposal → Accept → run → evidence». Это ручная приёмка за пультом
   (Keeper/Максим), НЕ playwright-автоматизация. Зафиксировать как один
   документированный smoke-чеклист, а не тест.
2. **StudioV2 интеграция дока** — smoke: док монтируется на `#/studio-v2`,
   рельс 36px ↔ док ~340px, LED по фазе, вёрстка рабочей области не ломается.
3. **Замечания UX-прохода** (двойной хедер, нерастянутая форма, запуск браузера
   в редакторе) — после их починки добавить по тесту-регрессу на каждое.
4. **Хоткеи** — Enter=Accept, Esc=Reject, 1..9=чипсы, Space=Take Control:
   убедиться что покрыты все четыре (сейчас buddyHotkeys 3 теста — сверить полноту).
5. **Адаптеры** (adapters.ts) — мапперы Boss→View: проверить что mapSkeleton /
   mapClarificationResult / mapProposalToDiff / mapRunToStepRadar / mapEvidenceMatrix
   имеют прямой тест, а не только косвенно через виджеты.
6. **Негативные сценарии Buddy** — incomplete, contradiction, disconnected, timeout,
   reject, manual edit, redaction: сверить против критериев KILL из
   `spike/2026-08-25-co-pilot-meta-poc.md` §9.

## 3. Формат ведения (под Buddy как босс)

- Единый реестр тестов: какие слои покрыты, какие в дырах, какой статус.
- Обновление — после каждой правки UI; без тихого устаревания тестов.
- Порог приёмки: `tsc 0` + точечный vitest по затронутым файлам; полный suite —
  только на релиз, не в отладке.
- Держать актуальной таблицу «Что уже покрыто» при каждом изменении числа тестов.
