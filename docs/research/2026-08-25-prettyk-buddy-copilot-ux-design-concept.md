# Дизайн-концепт и UX-видение: PrettyK Buddy (Internal Studio Co-Pilot)

> **Статус:** `concept / research` — продуктовое и UX-видение (Gemini Flash).  
> **Дата:** 25 августа 2026 года  
> **Владелец:** Максим  
> **Связанный PoC-пакет:** [`../spike/2026-08-25-co-pilot-meta-poc.md`](../spike/2026-08-25-co-pilot-meta-poc.md)  
> **Ключевой тезис:** Buddy — не чат-собеседник и не навязчивый поповер. Buddy — архитектурный штурман и живой экзоскелет оператора в Studio (`/studio`).

---

## 1. Продуктовая метафора и философия взаимодействия

В корпоративном софте большинство AI-ассистентов вызывают раздражение: они висят поверх интерфейса, требуют длинных диалогов и вываливают простыни неструктурированного текста.

В PrettyK действует принцип **«Инструмент хирурга, а не попугай»**:
1. **Ноль пустой болтовни:** Ответ модели — это всегда интерактивный виджет, готовый к действию.
2. **Мгновенный скан глазами:** Оператор считывает статус за 1.5 секунды через пиктограммы, чипсы и визуальные графы.
3. **Безусловный суверенитет оператора:** Модель не вносит изменений в проект втихую. Всё идёт через Reviewable Proposal и явный `Accept` (Enter).
4. **Доказательный финал (Evidence-First):** Любое утверждение модели («всё работает», «тест пройден») подтверждается конкретным артефактом (DOM-срез, HTTP-код, скриншот, тайминг).

## 2. Анатомия экранного присутствия: 3 состояния Buddy

```text
┌──────────────────────────────────────────────────────────────────────────────────┐
│  PrettyK Studio                                                  [ Editor | Studio ]│
├─────────────────┬──────────────────────────────────┬─────────────────────────────┤
│ EXPLORER (Tree) │ WORKSPACE CANVAS (Graph / Pills) │ BUDDY COPILOT DOCK (320px)  │
│                 │                                  │                             │
│ 📁 Pages        │   [ 🌐 Catalog ] ───▶ [ 🛒 Cart ] │ 🤖 Buddy                    │
│   📄 /catalog   │         │                        │ ─────────────────────────── │
│   📄 /cart      │         ▼                        │ «Разобрал твой intent:      │
│ 📁 Scenarios    │   [ 💳 Checkout ]                │  3 страницы, 1 сценарий»    │
│   ✨ AddToCart  │                                  │                             │
│                 │  ┌─────────────────────────────┐ │ ┌── Skeleton Card ────────┐ │
│                 │  │ ⚡ Live Run: Step 2 of 4     │ │ │ [✓] /catalog            │ │
│                 │  │ Target: /cart (DOM badge=1) │ │ │ [✓] /cart               │ │
│                 │  └─────────────────────────────┘ │ │ [?] /checkout (Auth?)   │ │
│                 │                                  │ └─────────────────────────┘ │
│                 │                                  │ [ Bearer ] [ Cookie ] [ Form]│
│                 │                                  │                             │
│                 │                                  │ [ Apply to Workspace ⏎ ]    │
└─────────────────┴──────────────────────────────────┴─────────────────────────────┘
```

### А. Launchpad Hero (Колыбель пустого проекта)
* **Контекст:** Оператор открыл Studio без загруженного `wired.json`.
* **Было:** Две кнопки «Новая конфигурация» и «Загрузить файл» на пустом черном фоне.
* **Стало:** По центру экрана — командная консоль Buddy с неоновым акцентом:
  > *«Опиши целевое приложение простыми словами, вставь OpenAPI/HAR или дай ссылку...»*
* Оператор вводит 1–2 предложения → прямо на экране из «тумана» материализуется первый граф страниц и сценариев.

### Б. Copilot Dock (Штурманская панель)
* **Контекст:** Активная работа над конфигурацией проверки.
* **Размещение:** Правая панель (320–380px) либо нижний выкатной ящик (`BottomDrawer`).
* **Эргономика:** Схлопывается в тонкий 36px рельс с LED-индикатором активности (Cyan = готов, Violet Pulse = думает, Amber = ждёт ответа).

### В. Gutter Whisper (Контекстный шепот в коде / графе)
* **Контекст:** Оператор вручную правит сценарий в Monaco или кликает узлы в Studio.
* **Поведение:** Никаких всплывающих окон. На полях строки Monaco зажигается мягкий глиф `✨`.
* **Клик по глифу:** Компактная плашка на 1 строку: *«Селектор кнопки изменился на бэкенде. Обновить до T0?»* + хоткей `[ Enter: Принять ]`.

## 3. Язык интерактивных микро-виджетов

Вместо текста markdown Buddy оперирует специализированными UI-блоками:

### 1. `SkeletonCard` (Интерактивная карта структуры)
Извлекает страницы и шаги из свободного описания:
```text
┌────────────────────────────────────────────────────────┐
│ 📐 Извлечённая структура (Intent Draft)                │
├────────────────────────────────────────────────────────┤
│ Страницы:                                              │
│   ☑️ Каталог товаров        (/products)                │
│   ☑️ Карточка товара        (/product/:id)             │
│   ☑️ Корзина                (/cart)                    │
│   ⬜ Админка                (исключено из scope)       │
│                                                        │
│ Сценарий: "Покупка товара в 1 клик" (4 шага)          │
│   1. Open /products                                    │
│   2. Click role="button" "Купить"                      │
│   3. Wait for /cart badge = 1                          │
│   4. Assert "Товар в корзине"                          │
└────────────────────────────────────────────────────────┘
```
* Прямо внутри карточки можно снять галочки, отредактировать названия или поменять порядок drag-and-drop.

### 2. `ClarificationChips` (Быстрые ответы в 1 клик)
Когда модели не хватает данных для построения шага:
* Выкатываются чипсы с хоткеями `1`, `2`, `3`:
  `[ 1: Bearer Token ]` `[ 2: Form Login ]` `[ 3: Публичный доступ ]`
* Оператор нажимает клавишу на клавиатуре — ответ моментально уходит в контекст.

### 3. `LiveDiffBanner` (Принятие изменений)
* Компактный сплит-дифф с цветовой кодировкой (зелёный/красный).
* Кнопка `[ Apply (Enter) ]` применяет изменения в `formData` и разворачивает ноды в дереве Explorer.

## 4. UX автономного фонового исследования («Discovery / Run Mode»)

Когда оператор поручает Buddy исследовать приложение или проверить сценарий вживую:

```text
┌───────────────────────────────────────────────────────────────────────────┐
│ ⚡ Buddy Discovery Active                       [ ⏸️ Take Control (Space) ]│
├───────────────────────────────────────────────────────────────────────────┤
│ [ 🌐 /catalog ] ➔ [ 👁️ AX Snapshot ] ➔ [ ⚡ Test Submit T0 ] ➔ [ ✓ OK ]     │
│ Telemetry: 124ms | Memory: 42MB | Target: juice-shop.local                │
└───────────────────────────────────────────────────────────────────────────┘
```

1. **Запрет слепых спиннеров:** Оператор всегда видит **Step Radar** — живую строку телеметрии текущего шага.
2. **Mini-Stage PiP (Picture-in-Picture):** В углу панели транслируется микро-превью экрана CDP Chrome `:9222`, показывающее реальные действия в браузере.
3. **Кнопка экстренного перехвата `Take Control`:** В любой момент пробелом или кликом оператор мгновенно останавливает фоновый запуск, забирает управление браузером, а весь накопленный результат остаётся в черновике.

## 5. Evidence-First матрица результатов

После прогона Buddy выдаёт не сухой статус «Done», а структурированное доказательство:

```text
┌──────────────────────────────────────────────────────────┐
│ 🏁 Результат проверки намерения                          │
├──────────────────────────────────────────────────────────┤
│ Интент: "Пользователь добавляет товар и видит корзину"   │
│                                                          │
│ 🟢 Доказано фактами (Evidence):                          │
│    • HTTP POST /api/cart ➔ 200 OK (38ms)                 │
│    • DOM: span.cart-count изменился с "0" на "1"         │
│    • AX Tree: name="Корзина (1)" role="link"             │
│    • Скриншот: [ 📷 Посмотреть snapshot экрана ]          │
│                                                          │
│ ⚠️ Замечания и риски (Advisory):                         │
│    • Кнопка "Купить" не имеет стабильного T0-имени       │
│    • Время ответа каталога > 500ms                       │
└──────────────────────────────────────────────────────────┘
```

| **Buddy Accent** | `#A855F7` ➔ `#38BDF8` | Неоновый градиент фиолетовый ➔ бирюзовый (мысли и действия ИИ) |

## 7. Мост к исполнителям (Boss & Flash)

* **Boss (Архитектура & Движок):**
  * Потребляет intent из чата → отдаёт нормализованный `SkeletonData`.
  * Реализует ограниченный `BoundedRunner` с остановкой по сигналу `Stop`.
  * Формирует `EvidenceMatrix` по итогам прогона без галлюцинаций.
* **Flash (Интерфейс & Виджеты):**
  * Верстает `CopilotDock`, `SkeletonCard`, `ClarificationChips` и `LiveDiffBanner`.
  * Интегрирует `Mini-Stage PiP` и неоновый LED-пульс в Studio.
  * Обеспечивает хоткеи (`Enter`, `Esc`, `1..9`, `Space` для Take Control).
