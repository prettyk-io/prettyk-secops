## 1. Архитектурный обзор и принцип трёх волн

Система строится вокруг принципа: **«Заменяемые инфраструктурные субстраты + Суверенное ядро безопасности PrettyK»**.
- **Git-фордж** (Gitea META default / GitLab / Forgejo) и **CI-раннер** (Woodpecker META default / Jenkins) — внешние исполнители.
- **PrettyK** владеет графом доменов и приложений, компилятором планов, брокером защищённых рантаймов, машиной состояний запуска, политикой допуска (Security Gates) и неизменяемым реестром улик (Evidence Ledger).

Чтобы избежать долгостроя и быстро получить работающий сквозной результат, реализация разделена на **3 последовательные волны**.

## 2. Детализация волн реализации

### 🎯 Волна 1: Сквозная струна (Steel Thread)
**Цель:** Получить первый рабочий сквозной контур по честному контракту:
`1 Domain → 1 App → Gitea Repo → Plan Compile → Batch (Build+Scan+Deploy) → Gate → SecOps Lab (:8767/ZAP) → Evidence Ledger`.

#### Состав Wave 1 (8 ключевых кирпичей):

| № | Компонент / Канон | Модуль | Роль и ответственность |
|---|---|---|---|
| **1** | `REPO-BINDING` (Gitea META) | Backend / Integration | Создание/линковка репозитория в локальном Gitea по REST API, регистрация вебхуков на push/tag. |
| **2** | `PLAN-COMPILER` (Core DAG) | Backend Core | Преобразование описания приложения и кирпичей (Bricks) в компилированный `PipelinePlan` с детерминированным `compiled_hash`. |
| **3** | `BATCH-DAG-IDEMPOTENT` | Backend Core | Логика выполнения пачек (Batches: build, static_scan, deploy, dynamic_test) с пропуском неизменённых пачек по `inputs_hash`. |
| **4** | `EXECUTION-ADAPTER` (Woodpecker META) | Backend / Adapter | Генерация `.woodpecker.yml`, вызов API/gRPC Woodpecker, стриминг сырых логов и статусов шагов. |
| **5** | `CAPABILITY-BROKER` (SecOps Lab) | Backend / Infra | Управление изолированными сессиями защитных инструментов (порты, ZAP demon API `:8080`, Playwright CDP `:9222`, KDT Live `:8767`) с привязкой к `run_id`. |
| **6** | `SECURITY-GATES` | Backend Core | Автоматический стоп-гейт (блокировка при наличии Critical/High уязвимостей) + ручной аппрув с подписью оператора. |
| **7** | `RUN-CONTROL-PLANE` (Lite) | Backend / State Machine | PostgreSQL (хранилище состояний Run/Batch/Job) + Valkey/SSE (живой стриминг прогресса в UI). |
| **8** | `EVIDENCE-CHAIN` (Ledger) | Backend Core | Неизменяемый журнал улик (хэш каждого шага, логи, артефакты, снапшоты) с полной цепочкой происхождения (provenance). |

#### Критерии готовности (DoD) для Волны 1:
1. Запуск через API/CLI одного приложения проходит стадии: сборка → сканирование → деплой на тестовый порт → вызов ZAP/Playwright в SecOps Lab.
2. При обнаружении критической уязвимости пайплайн останавливается на гейте.
3. Вся история выполнения и артефакты зафиксированы в `evidence_chain` с криптографическими хэшами.

### 🏗️ Волна 2: Мультидоменность КИТС, Иерархия и Фабрика QWEN
**Цель:** Масштабирование архитектуры до уровня реального ЦБ/Cosmoport с изолированными доменами и пакетным созданием.

#### Состав Wave 2:
1. **`FORGE-ADAPTER-MULTI` (Изоляция КИТС)**:
   - Поддержка нескольких независимых Gitea-инстансов (например, домен «Цифровой рубль» vs «Банковский контур»).
2. **`APP-GRAPH-HIERARCHY` (Уровни 0, 1, 2, 3)**:
   - `Уровень 0`: Библиотеки, базовые конфиги, общие кирпичи пайплайнов (non-deployable).
   - `Уровень 1`: Приложения/сервисы (1 app = 1 git repository).
   - `Уровень 2`: Логические группы приложений с общим групповым пайплайном сборки.
   - `Уровень 3`: Семейства систем и бизнес-домены.
3. **`DOMAIN-RBAC-SCOPE`**:
   - Ролевая модель с ограничением доступа по доменам и группам.
4. **`BRICK-INHERITANCE`**:
   - Каталог стандартных кирпичей (`prettyk-pure`) и возможность их переопределения на уровне домена (`cosmo-custom`).
5. **`COSMOPORT-IMPROVED` (QWEN Bulk Engine)**:
   - Приём промпта на естественном языке → сборка `DomainBootstrapPlan` → предпросмотр → создание 10 репозиториев, раскладка 9 drop-папок с исходниками, построение связей и черновика релиза.
6. **`GOST-REPORT-AUTO`**:
   - Автоматическая генерация подписанного Акта соответствия требованиям безопасности на основе `EvidenceChain`.

---

### 🔌 Волна 3: Расширения, Корреляция и Энтерпрайз-адаптеры
**Цель:** Поддержка legacy-инфраструктуры и глубокая аналитика безопасности.

#### Состав Wave 3:
1. **`EXECUTION-ADAPTER-JENKINS`**:
   - Адаптер для запуска сборок в существующей корпоративной инфраструктуре Jenkins.
2. **`FINDINGS-CORRELATION`**:
   - Дедупликация и корреляция находок из разнородных сканеров (SAST SonarQube/Trivy/CodeScoring + DAST ZAP + Fuzzer).
3. **`SIGNATURE-REWIND-INTEGRATION`**:
   - Интеграция таймлайна `EvidenceChain` с мастер-слайдером Studio для покадрового расследования атак и сбоев.

## 3. Брифинг для DeepSeek V4 Pro (Нарезка задач на Волну 1)

### Инструкция для исполнителя:
Модель `DeepSeek V4 Pro` должна произвести **финальную атомарную декомпозицию Волны 1 (Steel Thread)** и выдать **ровно 2 копипасты** (одну для Boss, одну для Flash).

### Распределение ролей:

#### 1. Копипаста для Boss (Архитектор / Heavy Backend Executor)
- **Фокус:** Внутренние механизмы, структуры данных, база данных, стейт-машина и адаптеры.
- **Задачи:**
  1. `core/domain`: Схемы Pydantic для `PipelinePlan`, `Batch`, `BatchDAG`, `SecurityGate`, `EvidenceRecord`.
  2. `core/compiler`: Реализация `PlanCompiler` (детерминированная сборка DAG, вычисление `compiled_hash` и `inputs_hash`).
  3. `state_machine`: Стейт-машина `RunControlPlane` в PostgreSQL (таблицы runs, batches, gates, evidence).
  4. `adapters/forge`: Клиент `GiteaForgeAdapter` (создание репозитория, инициализация, хуки).
  5. `adapters/execution`: Клиент `WoodpeckerExecutionAdapter` (генерация YAML, запуск, сбор логов).
  6. `broker/capability`: `SecurityCapabilityBroker` (аллокация портов и привязка к `run_id` для ZAP/Playwright).

#### 2. Копипаста для Flash (Быстрый исполнитель / Contracts & Client)
- **Фокус:** API эндпоинты, валидация, интеграционные тесты, CLI/SSE стриминг и типы фронтенда.
- **Задачи:**
  1. `api/routes`: REST API для запуска Run, получения статуса, подтверждения Security Gate (Manual Approve/Reject).
  2. `api/sse`: Стриминг событий выполнения Run и Batch в реальном времени через SSE/Valkey.
  3. `contracts/ts`: Генерация/синхронизация TypeScript интерфейсов для UI (RunStatus, BatchDAGView, GateModal).
  4. `tests/integration`: Смоук-тест сквозного сценария Wave 1 (mock Gitea + mock Woodpecker + реальный DAG compiler).
  5. `cli/runner`: Командная строка PrettyK для локального прогона одного приложения через Control Plane.
