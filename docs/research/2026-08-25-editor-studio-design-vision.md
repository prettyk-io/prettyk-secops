## 1. Манифест визуального стиля: Инструмент инженерного класса

PrettyK Authoring Workbench — это **не маркетинговый дашборд** и **не игрушечный визуальный конструктор**.  
Это высокоточный рабочий инструмент для инженера по автоматизации и SecOps-оператора, где эргономика современных сред разработки (Zed, Linear, JetBrains Fleet) соединяется со строгим характером кибер-безопасности.

### Главные визуальные принципы:
1. **Плотность без духоты (Dense & Crisp):** Каждый пиксель экрана работает на контекст задачи. Никаких гигантских пустых плашек и декоративных отступов в 48px.
2. **Трёхслойная глубина (3-Tier Layer Depth):** Глубочайший каркас хедера (`#04070E`) → Сайзеры и панели управления (`#0F1626`) → Холст редактора и браузерного вьюпорта (`#080C16`).
3. **Стекольные микробордеры (Glass Cyber Borders):** Тончайшие границы `1px solid rgba(92, 136, 245, 0.15)` разделяют рабочие зоны без визуального шума.
4. **Сдержанный акцентный свет:** Electric Ice Blue (`#38BDF8`) для активного фокуса и интерактивных пилюль, Vibrant Violet (`#7A1FA2`) для маркеров атак и фаззинга.
5. **Типографическая строгость:** Интерфейс — **Golos UI**, код и моноширинные параметры — **JetBrains Mono**.

## 3. Режимы компоновки (Dynamic Viewport Layouts)

Рабочее пространство динамически переключает пропорции в зависимости от текущего фокуса оператора:

### Режим 1: «Author Mode» (Написание и редактирование) — Дефолт
- **Explorer:** 220px (сворачиваемый до 40px икон-бара).
- **Monaco DSL Canvas:** `58%` ширины центральной зоны.
- **Browser Stage:** `42%` ширины (живое отражение шагов).
- **Bottom Drawer:** свернут в строку вкладок (32px).

### Режим 2: «Record Mode» (Интерактивная запись действий)
- **Explorer:** автоматический коллапс в узкий рейл (40px).
- **Browser Stage:** `60%` ширины (крупный вьюпорт, подсветка кликов, discovery locator hints).
- **Monaco DSL Canvas:** `40%` ширины (показывает в реальном времени дописываемый DSL-код с зеленым маркером diff).

### Режим 3: «Debug & Triage Mode» (Пошаговая отладка и триаж)
- **Monaco DSL Canvas:** `48%` ширины с подсветкой активного LED-шага (`StepLanternLed`).
- **Browser Stage:** `32%` ширины (синхронное состояние DOM).
- **Context / Variables Panel:** `20%` ширины (живые значения `$variables`, cookies, заголовки).
- **Bottom Drawer:** раскрыт на 240px (открыта вкладка `Timeline` + `Run Console`).

### Режим 4: «Zen Focus Mode» (Чистый код)
- **Explorer:** скрыт (`0px` / вызов по hotkey `Ctrl+B`).
- **Monaco DSL Canvas:** `100%` во весь экран с каноническим паддингом в 32 строки.
- **Browser Stage:** свернут в плавающую статус-пилюлю в статус-баре.

## 4. Спецификация экранов и ключевых узлов

### 4.1. Глобальный Хедер: Командный пульт воркспейса

```text
┌───────────────────────────────────────────────────────────────────────────────────────────────────────┐
│ [pretty<  │  EDITOR]   [📁 Auth Bypass Flow ▾]  [● 3 не зафиксировано]   [Target: https://app.local] │
│                                                                                                       │
│           [ Студия  |  Редактор ]              [✓ Валидация]  [💾 Черновик]  [📦 Коммит]  [▶ Запуск ▾]│
└───────────────────────────────────────────────────────────────────────────────────────────────────────┘
```

#### Элементы управления:
1. **Wordmark Lockup:**
   - Мастер-надпись `Pretty<` (белый `#F8FAFC` + шеврон `#38BDF8`).
   - Вертикальный разделитель `rgba(148, 163, 184, 0.25)`.
   - Суб-бейдж `EDITOR` в прохладном синем цвете `#8AB4F8` (`10.5px`, tracking `0.15em`).
2. **Селектор текущей проверки (Active Check Pill):**
   - Выпадающий список с недавними проверками, быстрый поиск, статус текущей проверки (`Draft` / `Validated` / `Running`).
3. **Счетчик несохраненных изменений (Dirty Badge):**
   - Мягкая янтарная точка `●` + текст `3 изменения`. При клике открывает быстрый Diff Drawer.
4. **Режимный переключатель `[ Студия | Редактор ]`:**
   - Расположен строго по центру хедера.
   - Ant/Radix Segmented Pill со скруглением 6px.
   - Активный элемент: фон `rgba(56, 189, 248, 0.15)`, цвет `#38BDF8`, тонкая рамка `1px solid rgba(56, 189, 248, 0.3)`.
5. **Группа действий справа:**
   - `[✓ Валидация]`: быстрая проверка AST и ссылок (без вызова тяжелого рантайма).
   - `[💾 Черновик]`: мгновенный autosave/flush в БД.
   - `[📦 Коммит]` (Фиолетово-синий акцент): открытие диалога создания контрольной точки.
   - `[▶ Запуск ▾]`: сплит-кнопка (Запуск текущего шага / Сценария целиком / Запуск с генерацией Allure-отчета).

#### Интерактивные фичи редактора:
- **Gutter Action Play `[▶]`:** клик на номер строки запускает только этот конкретный шаг в живом Browser Stage.
- **Step Status LED (`🟢 / 🔵 / ⚪ / 🔴`):** светодиодный маркер состояния шага (Queued, Running, Success, Failed).
- **Secret Badge Decoration:** секреты маскируются визуальной плашкой `[🔒 VAULT: ...]` без утечки в DOM.
- **Smart Autocomplete:** автодополнение MethodId, локаторов из зарегистрированных Pages и переменных воркспейса.

### 4.4. Browser Stage: Живой браузерный вьюпорт

Browser Stage — постоянная правая панель, подключенная к Playwright Browser Core / CDP `:9222`.

```text
┌───────────────────────────────────────────────────────────────────────────────────────────────────────┐
│ [ ◀ ] [ ▶ ] [ ⟳ ]  [ 🔒 https://bank.local/login                                      ]  [ ⚡ CDP 9222]│
├───────────────────────────────────────────────────────────────────────────────────────────────────────┤
│                                                                                                       │
│   ┌───────────────────────────────────────────────────────────────────────────────────────────────┐   │
│   │  ВХОД В БАНКОВСКИЙ КЛИЕНТ                                                                    │   │
│   │                                                                                               │   │
│   │  Логин:    [ admin                                ]                                           │   │
│   │  Пароль:   [ •••••••••••••                        ]                                           │   │
│   │                                                                                               │   │
│   │  ┌──────────────────────────────────────────────┐                                             │   │
│   │  │  [Войти в систему]                           │ ◄── [⚡ Role: button | Name: "Войти в систему"]│   │
│   │  └──────────────────────────────────────────────┘     [+ Добавить шаг в сценарий]             │   │
│   └───────────────────────────────────────────────────────────────────────────────────────────────┘   │
│                                                                                                       │
├───────────────────────────────────────────────────────────────────────────────────────────────────────┤
│ [⏺ Запись действий: ВКЛ]   [🎯 Инспектор локаторов]   [📸 Снимок экрана]   [📱 Размер: 1280×800 ▾]   │
└───────────────────────────────────────────────────────────────────────────────────────────────────────┘
```

#### Механика Browser Stage:
1. **Discovery Inspector Overlay:** при наведении курсора на любой элемент страницы поверх него рисуется неоновая рамка `#38BDF8` с карточкой role-first локатора (`role="button" name="Войти"`).
2. **Click-to-DSL Recorder:** клик по элементу в режиме записи мгновенно вставляет аккуратный шаг `Нажать role="button" name="..."` в активный сценарий.
3. **Zero-Desync State:** если раннер выполняет шаг в коде — страница в Browser Stage переходит на тот же URL и выполняет то же действие.

#### Изоляция браузерных контекстов

Фраза «одна браузерная сессия» не означает, что операторский браузер и runner делят cookies, localStorage и вкладки. Канон runtime-обёртки:

```text
BrowserSession
├── один browser process / CDP connection
├── OperatorContext — живая сессия, которую видит оператор
├── RunContext — чистый контекст конкретного прогона
└── DebugContext — контекст пошаговой отладки, если требуется
```

- Browser Stage по умолчанию показывает `OperatorContext`.
- Runner работает в отдельном `RunContext`.
- `DebugContext` используется для `Follow run` / `Inspect run`.
- Перенос авторизации выполняется только через явный storage-state snapshot, а не через совместное состояние.
- Чистый контекст создаётся явно и не должен появляться как скрытый второй Chromium.

Итоговая формула: **одна BrowserSession-обёртка, один управляемый browser runtime, несколько изолированных BrowserContext.**

```text
└───────────────────────────────────────────────────┴───────────────────────────────────────────────────┘
```

#### Semantic Diff — отдельный движок

Semantic Diff не строится как красивый рендер `JSON.stringify`. Это самостоятельный доменный слой:

```text
Wired snapshots
      ↓
Domain normalization
      ↓
Stable entity identity
      ↓
Semantic comparison
      ↓
Typed change set
      ↓
Studio renderer / Editor renderer / API / audit
```

Минимальный набор типов изменений:

```text
Scenario: ADD_STEP, REMOVE_STEP, MODIFY_STEP, MOVE_STEP,
          MODIFY_LOCATOR, MODIFY_ASSERTION, RENAME_ENTITY
Page:     ADD_LOCATOR, MODIFY_LOCATOR, REMOVE_LOCATOR
Resource: ADD_ENTRY, MODIFY_ENTRY, REMOVE_ENTRY
```

Движок обязан отбрасывать шум сериализации: порядок полей, runtime-метаданные, нестабильные внутренние ID и перестановки, которые не меняют поведения. Один результат используется в трёх местах:

- карточки изменений в Studio;
- side-by-side DSL diff в Editor;
- API, audit и approval flow.

До появления этого слоя Commit/Diff остаются только визуальным макетом и не передаются в production-исполнение.

## 6. Микро-интеракции и телеметрия

1. **Плавный ресайз панелей:** при перетаскивании сплиттеров Monaco Editor не перемонтируется и не сбрасывает курсор (`resizeObserver` с троттлингом 16ms / 60fps).
2. **Dirty Pulse:** при вводе символа в DSL в правом верхнем углу вкладки мягко загорается янтарный маркер `●` с fade-in 150ms.
3. **Step Execution Wave:** во время прогона сценария активная строка в Monaco подсвечивается мягким градиентным шлейфом `rgba(56, 189, 248, 0.08)`, а в Browser Stage на секунду подсвечивается затронутый элемент.
4. **Commit Feedback:** при успешном создании контрольной точки кнопка `[📦 Коммит]` дает короткую изумрудную вспышку `#3FB27F`, а статус-бар обновляет хеш коммита.

## 7. Инженерный gate: сначала Фаза A

Пакеты ниже нельзя выполнять в произвольном порядке. **Фаза A — обязательный gate** для всех следующих визуальных и продуктовых слоёв.

### Gate A: единый живой workspace

```text
AppShell
   ↓
CheckWorkspace
   ├── canonical formData / Wired
   ├── StudioWorkspace
   ├── EditorWorkbench
   └── persistence callbacks
```

Критерии закрытия:

1. Workbench получает реальные `formData`, `resourceContents`, `onFormDataChange` и save/run callbacks из shell.
2. Studio → canonical workspace → Wired → Editor показывает изменение.
3. Editor → canonical workspace → Wired → Studio показывает изменение.
4. Reload восстанавливает последний сохранённый draft.
5. Локальный `code` Workbench и `ScenarioDeckStore` не выступают источниками истины.
6. Переключение `[ Студия | Редактор ]` не теряет active document, dirty state и контекст проверки.

Только после этого разрешены:

```text
Gate A
  → draft persistence
  → Commit / immutable revision
  → Semantic Diff engine
  → Browser Stage and recorder
```

Commit Drawer, semantic diff cards и Browser Stage до закрытия Gate A — исключительно дизайн-макеты, не самостоятельные production-задачи.

## 9. Handoff братьям

### Boss

1. Начать с **Пакета A / Gate A**, не с Commit Drawer.
2. Вынести единый `CheckWorkspace` boundary и сохранить `StudioWorkspace` канонической логикой.
3. После Gate A сделать draft persistence, затем revision и semantic diff engine.
4. Не принимать локальный snapshot Editor за бизнес-состояние.

### Flash

1. Визуально собрать header и переключатель так, чтобы они управляли одной сессией, а не создавали новый state.
2. После Gate A собирать Browser Stage и discovery overlay.
3. Не рендерить Browser Stage как картинку, если контракт живого attach ещё не подключён.
4. Все visual proposals и recorder actions показывать через diff перед применением.

### Общий порядок

```text
Gate A: live workspace and round-trip
    ↓
Draft persistence
    ↓
Commit / revision
    ↓
Semantic Diff engine
    ↓
Browser Stage with isolated contexts
    ↓
Debugger / replay / AI suggestions
```

Это и есть пакет к возвращению братьям: **сначала связать дом, потом украшать фасад.**

## 10. Итог

Дизайн-вижн соединяет инженерную мощь и визуальную культуру:
- Оператор видит систему как **цельный и живой Workbench**.
- Studio и Editor работают синхронно в **одной сессии**.
- Browser Stage превращает написание автотестов в **быстрый визуальный процесс**.
- Версионирование через Commit и Diff защищает от потерь и дает **полную прозрачность изменений**.

Документ готов к передаче Boss и Flash для атомарной кодовой реализации. Первая задача — Gate A; всё остальное зависит от него.
