## Методология

- **Факт** — подтверждено официальной документацией, демо-стендом или скриншотами продукта конкурента.
- **Гипотеза** — логичное предположение на основе публичного позиционирования, но без прямого подтверждения в документации.
- **Опровергнуто** — проверено и не соответствует действительности.

## Сводная таблица: подтверждённые отличия PrettyK

| Отличие | Статус |
|---|---|
| **Consumer-agnostic DSL (Type/Click/Open/Wait) на Playwright** | ✅ Факт. Ни у одного конкурента не обнаружен открытый переносимый контракт такого типа. Katalon использует Groovy/Java-скрипты. |
| **Airgap / on-prem коробка** | ⚠️ Частично. PrettyK — точно airgap. У конкурентов on-prem опции возможны в enterprise-планах, но не подтверждены публично для всех. Требуется проверка enterprise-лицензий. |
| **Security + Functional в одном DSL** | ✅ Факт. Ни aqua/Testim/ACCELQ (functional), ни ZAP/Burp (security) не дают единого DSL на оба домена. |
| **Discovery Engine (автореверс форм без ручных локаторов)** | ⚠️ Гипотеза. В публичных материалах конкурентов не обнаружен. Требуется проверка. |
| **Двухуровневая продуктовая линейка (Automation → SecOps wedge)** | ✅ Факт. Ни у кого нет стратегии «дешёвый automation-вход → дорогой security-апгрейд» на общем DSL. |
| **QWEN внутри коробки (локальный AI)** | ✅ Факт. Конкуренты используют облачные AI-сервисы или не раскрывают модель. |

## Что готово для внешнего использования (маркетинг / сайт / питч)

1. **«Единственный инструмент, где QA-тесты и DAST-сканирование используют один язык сценариев»** — факт.
2. **«Airgap-коробка: ваши данные никогда не покидают контур»** — факт для PrettyK.
3. **«Playwright, не Selenium: современный browser engine»** — факт.
4. **«Переход от Automation к Security без дублирования работы»** — факт (стратегия wedge).

## Что НЕ готово для внешнего использования (пока)

1. **«Единственный DSL на рынке»** — не подтверждено для всех конкурентов. У них могут быть внутренние модели.
2. **«Все конкуренты — облачные»** — не проверено. Katalon и enterprise-версии других могут иметь on-prem.
3. **«Ни у кого нет Discovery Engine»** — гипотеза, требует проверки.
4. **«300 MB вся коробка»** — требует release-аудита.
5. **«У конкурентов нет assign/blank provisioning»** — гипотеза. Enterprise-workflow конкурентов не исследован.
