# Урок исполнения: сначала карта, потом пакет

> **Personal lesson · 18 августа 2026.**
> Инцидент: Studio graph groups — полезная фича начала закрываться слишком медленно.

## Что тормозило

1. **Серийная починка общего контракта.** После расширения `EditorFolders` я исправлял каждый fixture по ошибке TypeScript, хотя все потребители типа можно было собрать одним поиском.
2. **Проверка слишком дорогим шагом.** Полный `tsc --noEmit` запускался после мелких правок. Он нужен для финального прохода, не как итератор одной строки.
3. **Хрупкие массовые замены.** Regex-правки без карты совпадений породили дубли ключей и заставили тратить следующий цикл на уборку собственных следов.
4. **Смешивание слоёв графа.** Данные, layout, drag-preview и CSS менялись рядом. При регрессии с телепортацией ноды пришлось отделять причину от симптомов вместо того, чтобы сначала проверить hand-off preview → store.

## Новый рабочий цикл

**MAP → BATCH → VERIFY.**

- Сначала один поиск по всем потребителям изменяемого контракта, включая fixtures и тестовые фабрики.
- Затем один связный пакет: реализация, все прямые потребители и тестовые данные.
- Затем только узкие проверки нужной зоны. Полный typecheck — один раз, когда пакет готов.
- Если один класс ошибки повторился дважды, не продолжаю «дотачивать»: снова строю карту затронутых мест и правлю весь набор.

## Для интерактивного графа

Слои не смешивать: модель и связи → layout/store → pointer state → визуал. При проблеме во время drag сначала проверять, передаёт ли preview финальную позицию в store; не переписывать layout до подтверждения, что hand-off работает.

## DoD для скорости

- [ ] До первой правки собраны все потребители изменяемого типа/контракта.
- [ ] Одинаковые fixtures обновлены единым пакетом.
- [ ] Ни одна замена не делается без известного числа совпадений.
- [ ] Проверки соответствуют зоне изменения, а не запускаются по привычке.
- [ ] Пользователь получает результат с фактами, а не поток промежуточных шагов.
