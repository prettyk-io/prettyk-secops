# APP-GRAPH-HIERARCHY: Иерархия приложений Level 0–3

> `lane: ready` · 27 авг 2026. Research: [`cosmoport-domain-model.md`](../research/2026-08-27-cosmoport-domain-model.md).

## Тезис

Приложения внутри Domain организованы в четырёхуровневую иерархию: Level 0 (библиотеки/конфиги/кирпичи), Level 1 (apps/services, 1 app = 1 repo), Level 2 (группы), Level 3 (группы групп). Наследование политик и кирпичей идёт сверху вниз с возможностью переопределения.

## Ключевые свойства

- **Level 0** — не деплоится. Поставляет библиотеки, конфиги, определения Pipeline Bricks.
- **Level 1** — атомарная единица: 1 app = 1 git repository. Свой жизненный цикл.
- **Level 2** — логическая группировка. Политики и кирпичи наследуются всеми apps внутри.
- **Level 3** — группа групп. Обычно = бизнес-домен или контур.
- **Наследование:** политика, назначенная на Level 3 → все Level 2 → Level 1. Переопределение на нижнем уровне разрешено.

## Что нужно построить

- Модель данных: `AppNode { id, domain_id, name, level, parent_id, repo_binding_id }`.
- API: CRUD app, перемещение между группами, построение дерева.
- UI: иерархическое дерево приложений (вместо плоской лесенки).
- Политика наследования: назначение Brick на Level 2/3 → проецируется на Level 1.

## Честная «не обещаем»

- Динамическое определение иерархии из кода/конфигов — out of scope. Иерархия задаётся явно.
- Циклические зависимости между уровнями — не поддерживаются и не проверяются в v1 (валидация позже).
