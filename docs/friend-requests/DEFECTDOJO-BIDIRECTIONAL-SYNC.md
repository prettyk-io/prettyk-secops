# Friend-Request: Двусторонняя синхронизация с DefectDojo и управление жизненным циклом уязвимостей

> **ID:** `DEFECTDOJO-BIDIRECTIONAL-SYNC`  
> **Статус:** `ready`  
> **Роль / Исполнитель:** Flash / Boss  
> **Слой:** Backend (`orchestrator/services/dojo/`) ↔ Admin FE (`cosmo/src/admin/`)

---

## 1. Продуктовая суть и замысел

Интеграция SecOps Lab с **DefectDojo** переводится из режима «ручного просмотра таблицы» в **полноценный двусторонний движок синхронизации (Bidirectional Sync)**:
1. **Push находок:** По завершении прогона сценария или фаззинга обнаруженные уязвимости (с CWE, CVSS, шагами воспроизведения и HTTP-запросами) автоматически пушатся в DefectDojo Engagement.
2. **Дедупликация и фингерпринтинг:** Расчет хеша уязвимости (FNV-1a / SHA256 по эндпоинту + параметру + типу атаки) для предотвращения спама дубликатами.
3. **Обратный импорт статусов:** Если ИБ-специалист в интерфейсе DefectDojo пометил уязвимость как `False Positive` или `Risk Accepted`, SecOps Studio и Allure3 подтягивают этот статус и подавляют повторные алерты при регулярных проверках.

---

## 2. Архитектура и API-контракт

1. **Модуль синхронизации (`orchestrator/services/dojo_sync.py`):**
   - Фоновый воркер с очередью повторных попыток (Exponential backoff при недоступности Dojo).
   - Поддержка `Dojo REST API v2` (`/api/v2/findings/`, `/api/v2/import-scan/`).
2. **Контроллер в Admin UI (`cosmo/src/admin/DojoSyncManager.tsx`):**
   - Ручной триггер «Sync Now».
   - Индикация последнего времени синка и счетчик активных/подавленных находок.
   - Настройка маппинга продуктов (Product ID / Engagement ID).

---

## 3. Критерии приёмки (DoD)

- [ ] Успешный прогон с найденными XSS/SQLi создает Finding в DefectDojo с корректным severity.
- [ ] Повторный прогон не создает дубликат, а инкрементирует счетчик `nb_occurences` в Dojo.
- [ ] При статусе `False Positive` в Dojo повторный отчет в Allure3 маркирует тест как `Muted / Suppressed`.
- [ ] Unit & Component тесты покрывают сетевые ошибки и таймауты API Dojo.
