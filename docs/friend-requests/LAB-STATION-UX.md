# Lab Station UX — полная архитектура

> **Feature Request.** Profile: `secops-lab-pure`. Lane: `ready`.
> Пересборка UI станции атак `/lab` (Burp Killer). Бэкенд-движок готов (`intruder_engine.py`).
> Задача: заменить плоский нефункциональный UI на пошаговый визард + Suite Builder.

## Текущее состояние

Бэкенд: рабочий движок Intruder (sniper, battering_ram, pitchfork, cluster_bomb), энкодеры, Grep Match/Extract, многопоточность. API: `/api/lab/intruder/start|stop|status|results|detail` на KDT Live `:8767`. Фронтенд: все контролы есть, но свалены на один экран. Переключение режима атаки не меняет UI. Нет счётчика запросов до запуска. Нет пошагового ведения.

## Чего хочет заказчик

Оператор без опыта работы с Burp Suite заходит в `/lab` и за несколько шагов настраивает и запускает атаку. Система ведёт его, показывает что происходит на каждом шаге, даёт живой визуальный фидбек. Даже полный новичок понимает что делает.

Второй режим — сборка цепочки атак (Suite) с передачей сессии между ними и визуализацией прогресса в виде «змейки». Результаты можно сохранить как evidence.

## Общий принцип

- Всё разбито на **модули**, каждый модуль — самостоятельный компонент
- Модули которые не готовы к реализации сейчас — отображаются как **заглушки** с пометкой `to evolve`
- Архитектура закладывается сразу под полный функционал, никакого «MVP с переписыванием потом»
- Общие компоненты (словари, grep, таблица результатов) переиспользуются между Single Attack и Suite Builder

## Компонентная архитектура

```
LabWorkspace (корень, управляет режимом: single | suite)
├── LabSessionProvider (lab_instance_id, state)
│   ├── SingleAttackWizard
│   ├── SuiteBuilder
│   ├── ResultsView (общий)
│   ├── PayloadSetPanel (общий, переиспользуется)
│   ├── GrepPanel (общий, переиспользуется)
├── HistoryPanel          ← to evolve (заглушка)
├── TemplatesPanel        ← to evolve (заглушка)
└── SettingsPanel         ← to evolve (заглушка)
```

### Общие компоненты

- **PayloadSetPanel** — один набор словарей: пресеты, свой список, генераторы (Numbers, Brute Force), загрузка файла, энкодеры + префикс/суффикс, живой превью
- **GrepPanel** — Match + Extract паттерны, кнопка «Тест» на sample-ответе
- **ResultsTable** — виртуализированная таблица с цветными клетками статусов, фильтры, поиск
- **ResultsInspector** — split Request | Response (Raw / Headers / Render), для одиночного просмотра и для Suite

## Модуль 1: Lab Session

**Given:** оператор заходит на `/lab`.
**When:** страница загружается.
**Then:** создаётся сессия с `lab_instance_id` (UUID). Сессия живёт в памяти браузера + бэкенд держит `_ATTACK_SESSIONS` пока атака идёт. При уходе со страницы — сессия дропается через TTL на бэкенде.

**To evolve:** сохранение сессии в localStorage между перезагрузками. История сессий — Модуль 4.

### DoD
- При заходе на `/lab` генерируется `lab_instance_id`
- `lab_instance_id` передаётся во все API-запросы к Live-серверу
- При закрытии вкладки / уходе — бэкенд-сессия дропается по TTL (N минут)

## Модуль 2: Single Attack Wizard

5 последовательных шагов с прогресс-баром сверху. Каждый шаг — отдельная секция. Кнопка «Далее» активна только когда шаг заполнен. Можно вернуться на предыдущий шаг.

### Шаг 1 — Цель (Target)

**Given:** оператор на Шаге 1.
**When:** вставляет RAW HTTP запрос.
**Then:**
- Система автоматически парсит метод, URL, заголовки, тело
- Показывает распарсенные поля раздельно (не monospace месиво)
- Есть переключатель «Raw» / «Form» — в Raw видно сырой текст, в Form — поля раздельно
- Зелёный индикатор: «Запрос распознан: POST /api/login»
- Кнопка «Далее» активна

**DoD:** вставленный HTTP парсится. Поля видны раздельно. Raw/Form переключатель работает.

### Шаг 2 — Позиции (Positions)

**Given:** запрос распознан.
**When:** оператор кликает по параметру / заголовку / части тела.
**Then:**
- На месте клика ставятся §маркеры§
- Каждая позиция — цветной pill с авто-именем (`param_q`, `body_user`, `cookie_token`)
- Имя можно переименовать
- Счётчик: «3 позиции отмечено»
- Кнопка «Авто-расстановка» — ищет query-параметры, POST-поля, cookie, заголовки и отмечает их
- Минимум 1 маркер для кнопки «Далее»

**To evolve:** drag-and-drop маркеров, визуальное выделение overlapping positions.

**DoD:** клик → маркер. Pill с именем у каждой позиции. Авто-расстановка находит параметры. Минимум 1 маркер.

### Шаг 3 — Режим атаки (Attack Mode)

**Given:** позиции расставлены.
**When:** оператор выбирает режим.
**Then:**
- 4 большие карточки (не radio button), каждая с иконкой и описанием
- При выборе — **анимированная диаграмма** на карточке: стрелки показывают как пейлоады распределяются по позициям
- Живой счётчик под карточками: «Будет отправлено **N** запросов (~M секунд при 5 потоках)»
- Выбранная карточка — градиентная подсветка (brand gradient: blue → violet)

**Описания карточек:**
- 🎯 Sniper: «Один словарь. Каждый пейлоад по очереди в каждую позицию. N позиций × M пейлоадов.»
- 🔨 Battering Ram: «Один словарь. Один пейлоад одновременно во все позиции. M запросов.»
- 🍴 Pitchfork: «N словарей. Пейлоады параллельно: первый из словаря 1 → позиция 1, из словаря 2 → позиция 2. Минимум по длине словарей.»
- 💣 Cluster Bomb: «N словарей. Все комбинации (декартово произведение). Может быть ОЧЕНЬ много запросов.»

**DoD:** 4 карточки с анимированными диаграммами. Живой счётчик + ETA. Градиент на выбранной.

### Шаг 4 — Словари (Payload Sets)

**Given:** режим выбран.
**When:** оператор настраивает словари.
**Then:**
- Количество наборов пейлоадов зависит от режима:
  - Sniper / Battering Ram — 1 набор
  - Pitchfork / Cluster Bomb — по 1 набору на каждую позицию
- Каждый набор показывает имя позиции к которой привязан
- **Пресеты:** кнопки SQLi, XSS, SSRF, Auth, Boundary — загружают готовый словарь
- **Свой список:** textarea, одна строка = один пейлоад
- **Генератор чисел:** поля «от», «до», «шаг». Живой превью: «1, 3, 5, 7, 9...»
- **Brute Force:** поля «алфавит», «мин. длина», «макс. длина». Превью: «aaa, aab, aac...»
- **Загрузка файла:** перетащить .txt или выбрать через диалог
- Живой превью: «Первые 5 пейлоадов: admin, guest, root, test, user»
- **Обработка:** энкодеры (url, base64, hex, md5) + префикс/суффикс — на каждый набор

**To evolve:** больше payload types (dates, character blocks, runtime file, custom iterator).

**DoD:** количество наборов = количество позиций (для Pitchfork/Cluster Bomb) или 1 (Sniper/Battering Ram). Каждый набор имеет пресеты + список + генераторы + энкодеры + превью. Все обязательные наборы заполнены → «Далее» активно.

### Шаг 5 — Пуск и результаты (Execute & Results)

**Given:** все шаги заполнены.
**When:** оператор жмёт «Запустить атаку».
**Then:**
- Модальное окно подтверждения: «1400 запросов на 127.0.0.1:3000, ~23 секунды»
- Кнопки: «Запустить», «Отмена»

**После запуска — экран результатов:**
- Прогресс-бар с числом выполнено/всего и процентами
- req/sec (живой счётчик) + ETA (оставшееся время)
- Таблица результатов:
  - Колонки: #, Payload, Status (цветной tag: 2xx=зелёный, 4xx=жёлтый, 5xx=красный, ERR=серый), Length (байт), Time (ms), Grep Match (фиолетовый pill «MATCH»)
  - Аномалии подсвечены: строки где status ≠ 2xx или length выбивается из среднего — другим оттенком фона
  - Клик по строке → ниже раскрывается инспектор: Request слева, Response справа
- Инспектор Response: три режима — Raw (текст), Headers (таблица ключ-значение), Render (iframe/HTML)
- Фильтры над таблицей: чекбокс «Только ошибки (4xx/5xx)», чекбокс «Только Grep Match», поле поиска по пейлоаду
- Кнопка «Остановить атаку» (красная, видна пока идёт)

**После завершения:**
- Сводка: всего запросов, успешных (2xx), ошибок (4xx/5xx/ERR), grep-match
- Кнопка «Сохранить результаты» → скачивается JSON (конфигурация + все ответы)
- Кнопка «Добавить в Suite» → переход в Suite Builder, текущая атака — первая в цепочке
- Кнопка «Новая атака» → сброс к Шагу 1

**To evolve:** response diffing (сравнить два ответа в инспекторе), anomaly detection (авто-подсветка статистических выбросов).

**DoD:** подтверждение перед запуском. Прогресс-бар + req/sec + ETA. Таблица с цветными статусами. Подсветка аномалий. Инспектор Request/Response. Фильтры. Остановка. Сохранение JSON.

### Grep Match / Extract (часть Шага 4)

**Given:** оператор на Шаге 4.
**When:** настраивает Grep.
**Then:**
- «Grep Match» — паттерны через `|`, каждый можно пометить флажком «regex»
- «Grep Extract» — regex с capture group, извлечённое значение получает имя (для передачи в Suite)
- Кнопка «Тест» — в модалке показывает на sample-ответе что сматчилось / извлеклось

**DoD:** Match показывает pill в таблице результатов. Extract собирает значения для передачи между атаками Suite. Кнопка «Тест» работает.

## Модуль 3: Suite Builder

Сборка и исполнение цепочки атак с передачей данных между ними.

### Сборка Suite

**Given:** оператор в режиме Suite Builder.
**When:** добавляет атаки в цепочку.
**Then:**
- Каждая сконфигурированная атака (из Single Attack Wizard) добавляется в цепочку
- Порядок атак — drag-and-drop (вертикальный список с ручками перетаскивания)
- Между атаками — настройка **передачи данных**:
  - Cookie: «Взять Set-Cookie из ответа Атаки N → добавить в заголовок Cookie запроса Атаки N+1»
  - Grep Extract: «Взять значение `token` из Extract Атаки N → подставить в параметр `?auth=` Атаки N+1»
  - Condition: «Продолжать только если status = 2xx»
- Общий счётчик под цепочкой: «Всего 180 запросов по 3 атакам, ~8 секунд»
- Кнопка «Сохранить Suite как шаблон» (to evolve)
- Кнопка «Запустить Suite»

**To evolve:** fork атаки (разные словари на одну конфигурацию), параллельное исполнение независимых атак.

**DoD:** цепочка из 2+ атак. Drag-and-drop порядка. Настройка передачи cookie и extract. Общий счётчик.

### Исполнение Suite — Змейка (Snake View)

**Given:** Suite собран.
**When:** оператор жмёт «Запустить Suite».
**Then:**
- Экран переходит в режим живой змейки
- Каждая атака в цепочке — горизонтальная полоса:
  - Слева: номер и название атаки
  - Прогресс-линия внутри полосы
  - **Сетка клеток** — каждая клетка = один запрос:
    - `✓` зелёная — 2xx
    - `✗` жёлтая — 4xx
    - `💀` красная — 5xx / ошибка
    - `💜` фиолетовая — grep match найден
    - `●` пульсирующая — отправляется сейчас
    - Пустая — ещё не отправлена
- Атаки соединены вертикальной линией (змейкой), показывающей направление потока
- Завершённая атака: зелёная галочка + мини-сводка (N запросов, M match)
- Текущая атака: req/sec + ETA
- Ожидающие атаки: затемнены
- Общий прогресс-бар над всей змейкой

**To evolve:** интерактивная змейка (клик по атаке → раскрыть детали inline), pause/resume отдельной атаки.

**DoD:** змейка соединяет атаки. Клетки раскрашены по статусу. Текущая пульсирует. Прогресс общий.

### Results & Evidence

**Given:** Suite завершён.
**When:** оператор смотрит итоги.
**Then:**
- Сводная таблица: по каждой атаке — запросов, успешных, ошибок, grep-match
- Список «Находки» — все grep-match из всех атак единым списком
- Клик по атаке в змейке → раскрывается её таблица результатов (такая же как в Single Attack)
- Кнопка «Save Results & Evidence» → скачивается полный JSON (конфигурация Suite + все ответы + находки)
- Кнопка «Repeat Suite» → перезапуск той же цепочки
- Кнопка «New Suite» → сброс

**To evolve:** сравнение результатов между прогонами Suite, regression detection, экспорт в Allure/Dojo.

**DoD:** сводная таблица Suite. Список находок. Сохранение JSON. Повторный запуск.

## Приоритет реализации

Всё что без пометки `to evolve` — полная реализация сейчас. Всё с пометкой `to evolve` — визуальная заглушка в UI (серая кнопка/вкладка с подписью «to evolve»), не ломает вёрстку, не делает запросов, архитектурно место заложено.

### Что реализуется полностью
- Модуль 1: Lab Session

### Что делается заглушкой
- Модуль 4: История и шаблоны
- Модуль 5: Расширенные настройки
- Модуль 6: Анализ результатов

## DoD (30-second test)

- **(а)** Оператор без опыта заходит в `/lab`, проходит 5 шагов, видит счётчик запросов, запускает атаку, наблюдает цветные результаты
- **(б)** Оператор добавляет вторую атаку в Suite, настраивает передачу cookie, запускает — видит змейку с клетками
- **(в)** Заглушки «История», «Шаблоны», «Настройки» видны серым с пометкой «to evolve»
- **(г)** При переключении Sniper → Pitchfork → Cluster Bomb UI адаптируется (меняется число наборов словарей и счётчик)
- **(д)** Все существующие тесты проходят (`LabWorkspace.test.tsx`, `test_intruder_engine.py`)
- **(е)** Кнопка «Сохранить результаты» отдаёт валидный JSON с полной конфигурацией и ответами
