# QWEN3-ALERT-ASSISTANT: локальная AI-модель для анализа алертов

> `lane: ready` · 20 авг 2026. Profile: `secops-lab-pure`.

## Тезис

Локальная модель Qwen3-1.7B (Apache 2.0) в Docker-контейнере, развёрнутая на KDT Live `:8766` или соседнем порту. Анализирует scanner-алерты: классификация severity, отсев false positive, сравнение HTTP-ответов, приоритизация находок. Не заменяет детекшн-движок scanner — работает как ассистент аналитика поверх.

## Почему Qwen3-1.7B

| Параметр | Значение |
|---|---|
| Параметры | 1.7B |
| RAM (Q5_K_M) | 1.7 GB |
| Лицензия | Apache 2.0 |
| Русский | Да, 100+ языков |
| Thinking toggle | Да (быстрый режим + глубокий анализ) |
| JSON output | Документированно сильный |

## Архитектура

```
scanner alert (JSON) → Qwen3-1.7B (llama.cpp :8766) → KDT Live → Results/Dojo
                                                         ↓
                                                   Аналитик видит:
                                                   - severity classification
                                                   - FP confidence score
                                                   - diff-анализ ответов
                                                   - рекомендация
```

Модель работает в двух режимах:
- **thinking=off** — быстрая классификация (severity, тип атаки). Латенси ~200-400ms
- **thinking=on** — глубокий diff-анализ двух HTTP-ответов, контекстное объяснение. Латенси ~1-3s

## Что делает

### Given: scanner-алерт с uncertain confidence
**When:** алерт поступает в KDT Live.
**Then:** модель анализирует его и выдаёт:
- Классификацию severity (low/medium/high/critical)
- FP confidence (0-100% — насколько вероятно что это false positive)
- Краткое обоснование на русском
- Рекомендацию: «проверить вручную», «подтверждено», «ложное срабатывание»

### Given: два HTTP-ответа (базовый и с инъекцией)
**When:** оператор запрашивает diff-анализ.
**Then:** модель в режиме thinking=on сравнивает ответы и сообщает:
- Есть ли разница в поведении
- Что именно изменилось (статус, тело, заголовки)
- Похоже ли на эксплуатацию уязвимости

### Given: список алертов после прогона
**When:** прогон завершён.
**Then:** модель приоритизирует алерты:
- Какие чинить первыми (impact × exploitability)
- Какие можно отложить
- Какие точно false positive

## Этапы реализации

### Этап 1: Smoke-тест (Boss, 30 мин)
- Установить ollama, скачать `qwen3:1.7b`
- Прогнать 20 реальных scanner-алертов через модель
- Замерить латенси, оценить качество

**DoD:** модель отвечает на русском, классифицирует severity, даёт осмысленные ответы.

### Этап 2: Docker-упаковка (Boss, 30 мин)
- `Dockerfile`: llama.cpp + Q5_K_M модель + HTTP API
- Образ ~1.5 GB, gap-ready
- Порт `:8766`, API: `POST /api/ai/classify`, `POST /api/ai/diff`, `POST /api/ai/prioritize`

**DoD:** `docker run`, `curl -X POST /api/ai/classify` → валидный JSON-ответ.

### Этап 3: Интеграция с KDT Live (Flash, 2 часа)
- Добавить endpoints в `live_server.py`:
  - `POST /api/ai/classify` → принимает scanner-алерт, возвращает классификацию
  - `POST /api/ai/diff` → принимает два ответа, возвращает diff-анализ
  - `POST /api/ai/prioritize` → принимает список алертов, возвращает приоритизированный
- Проксирование запросов к llama-server `:8766`
- Кеширование результатов (одинаковый алерт → не гонять модель повторно)

**DoD:** curl-запросы к Live возвращают AI-разметку.

### Этап 4: UI-отображение (Flash, 2 часа)
- В Results/Dojo — рядом с каждым алертом показывать:
  - AI severity classification (если отличается от scanner — подсветить)
  - FP confidence badge (зелёный/жёлтый/красный)
  - Кнопка «AI Diff» → модалка с diff-анализом
- В Results summary — AI-приоритизация списка находок

**DoD:** алерты в Results показывают AI-разметку. Кнопка diff работает.

## Out of scope

- Fine-tune модели (нужен датасет 500-1000 размеченных алертов — позже)
- Замена scanner-детекшена моделью — модель ТОЛЬКО ассистент, не source of truth
- GPU-инференс (CPU достаточно для 1.7B)
- Сертификация модели для ЦБ (позже, перед внедрением)

## Технические требования

- llama.cpp (C++, без Python-зависимостей для инференса)
- Q5_K_M квантизация (~1.7 GB RAM)
- Docker-образ < 2 GB
- API с таймаутом 5s (thinking=off) / 10s (thinking=on)
- JSON-ответы строго типизированы
